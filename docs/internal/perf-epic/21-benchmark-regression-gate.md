# #21 — Benchmark target and regression gate

## Change

Added the `Benchmark` Nuke target. It publishes the current source in Release configuration, creates temporary
synthetic blogs with 1,000, 2,000, or 4,000 posts and three tags per post, then builds each site with and without
a recent-posts sidebar. The sidebar reads the date-sorted page view and renders the ten newest posts.

Each of the six scenarios runs five times. Parse and Create phase medians are compared independently with the checked-in
`.nuke/benchmark-baseline.json`; the target fails when a scenario is more than 25% slower. Benchmark builds use
two logical processors for consistent parallelism. Raw runs, medians, baseline comparisons, and pass/fail status
are written to `artifacts/benchmark.json`, including the SDK and runtime versions. CI runs the target in its own
job and uploads that JSON even when the regression gate fails. SDK selection is pinned to the .NET 10 feature band;
the target rejects any SDK outside .NET 10.

## Benchmark

Local Release run on Linux x64 (`MassaPCLinux`, kernel `7.0.0-38-generic`, glibc 2.43), using .NET SDK 10.0.112,
.NET runtime 10.0.12, and two logical processors. Five runs per scenario. The baseline was refreshed locally with
`./build.sh Benchmark --update-benchmark-baseline --configuration Release --runtime-identifier linux-x64`; it is
provisional and is **not a CI-generated baseline**.

| Scenario | Parse median (ms) | Create median (ms) |
|---|---:|---:|
| 1,000 posts, sidebar off | 42 | 88 |
| 1,000 posts, sidebar on | 42 | 89 |
| 2,000 posts, sidebar off | 69 | 130 |
| 2,000 posts, sidebar on | 69 | 130 |
| 4,000 posts, sidebar off | 124 | 201 |
| 4,000 posts, sidebar on | 123 | 213 |

The complete raw-run data is in `artifacts/benchmark.json`. The baseline file records source `local`, runner
`MassaPCLinux`, SDK 10.0.112, and runtime 10.0.12. Its refresh command compares each measurement to itself, so that
run alone does not validate regression detection; the default target and a real-code slowdown still need verification.

The measured baseline is local and cannot satisfy the CI-baseline acceptance criterion. Keep the #21 CI job
non-required until a baseline artifact generated by the CI runner has been reviewed and committed.
